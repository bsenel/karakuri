### 2. What is durable must match what the user saw, and the checkpoint store must stay up

- **Claim.** After a cancel or a failure, people expect to resume from what was on screen; they get an older checkpoint, a re-run, or a broken thread.
- **Sources.** Two threads in one tracker (langchain-ai/langgraph), one population; they are the first two of its open issues sorted by +1 reactions. (https://github.com/langchain-ai/langgraph/issues?q=is%3Aissue+is%3Aopen+sort%3Areactions-%2B1-desc, read 2026-10-08) [E] The 2026-10-04 report listed both by title.

(https://api.github.com/repos/langchain-ai/langgraph/issues/5672, read 2026-10-08) [Q, fragments]

### 4. The MCP client sends arguments the server never declared

- **Claim.** An agent framework passes its own bookkeeping fields through to MCP tools, strict servers reject the call, and users patch their servers to cope.
- **Sources.** One thread in one tracker (n8n-io/n8n #21500), chosen as the most-reacted of the four n8n issues whose counts were fetched. One population.
- **Counts.** 11 reactions, all +1; 27 comments.
- **What the author needed** (tim-schneider-elo, 3 November 2025): "When I want to execute a tool, it fails, as the MCP Client Tool sends a `toolCallId`, which is not expected by my server." and "The MCP Client Tool should only send the needed arguments, that are explicitly asked for by the MCP Server." (https://api.github.com/repos/n8n-io/n8n/issues/21500, read 2026-10-08) [Q]
- **Replies.** Other users report the same on other servers: icebob, 4 November 2025, quoting an Alpha Vantage server: "top_gainers_losers() got an unexpected keyword argument 'toolCallId'"; neerax, 8 November 2025: "The same here (1.119.0) with the following extra parameters:", which the extract lists as sessionId, action, chatInput and toolCallId. A month in, on a newer release: Tynamix, 4 December 2025: "I also recreated the mcp client node and it still sends all input parameters." The maintainer reply: krisn0x, 5 December 2025: "Closing this as duplicate to consolidate the investigation, please check #21716". TomTom101 then linked pull request #23167 and asked on 14 January 2026 whether a user had upgraded to the releases named there; the thread names no fixing release. In March 2026 a triager asked whether it persisted, the author answered "I'm running a different setup now, so I can't really compare it to the old ways.", and the last comment is the tag "#closed:working-as-expected". (https://api.github.com/repos/n8n-io/n8n/issues/21500/comments?per_page=100, read 2026-10-08) [Q for quoted text] The API gives the closure as duplicate, on 16 March 2026. #21716 and the pull request were not opened.
- **The sentence that carries the point:** "The MCP Client Tool should only send the needed arguments, that are explicitly asked for by the MCP Server." [Q]
